# 3D Editor Stable v0.10.0 — BVH-ускорение точной кисти

## Задача

В v0.9 каждый луч пальца проверял все треугольники видимого примитива (линейный O(N) перебор). Для GLB персонажей с сотнями тысяч треугольников это создаёт лишнюю нагрузку CPU и задержку жестов.

## Реализация

- `TriangleBvh` создаёт бинарное BVH-дерево для каждого glTF-примитива при асинхронной загрузке GlbSurfacePicker. Внутренние узлы хранят AABB; листья содержат не более 12 треугольников.
- Разделение по самой длинной оси центроидов, in-place partition за O(N); при совпадающих координатах — гарантированное деление по количеству. Это предотвращает бесконечную рекурсию и крайне несбалансированные листья.
- Поиск проходит дерево, сначала более близкий узел, отсекая всё за текущим ближайшим пересечением. Для самих треугольников остался Möller–Trumbore и прежняя проверка ближайшего видимого материала.
- Геометрия, радиус, сила, история кисти, экспорт и подпись приложения не меняются.
- Границы и ошибки чтения исходного GLB проверяются до построения дерева. Ограничение в 2 млн треугольников сохраняется.

## Тесты и критерии

- На сетке 32×32 проверяется корректное расстояние по множеству точек и отсутствие ложных попаданий.
- На сетке 128×128 (32 768 треугольников) трассировщик должен проверить менее 1/12 всех треугольников и посетить менее 1/8 узлов относительно количества треугольников.
- Проверяются предел расстояния, параллельный луч, совпадающие центроиды и корректность расчёта ближайшего видимого материала старыми тестами.
- Android CI на текущем SHA: check_standard + Kotlin compile + JUnit + assembleDebug.
- На Lenovo Legion Y70 необходимы аппаратные проверки FPS/задержки на обоих GLB; время ускорения в миллисекундах без устройства не заявляется.
