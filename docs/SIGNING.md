# Постоянная подпись APK

Android 3D Editor использует постоянный закрытый ключ разработчика. **Не добавляйте .jks, пароли или base64 ключ в GitHub-код.**

- Alias: `android-3d-editor`
- Fingerprint SHA-256: `E6:53:56:97:AB:4F:96:0F:89:AC:FC:5B:EE:3C:80:FF:E5:3E:62:EC:C7:C1:39:25:02:5B:91:E1:CC:98:D0:C5`
- Требование Android 11+ для targetSdk ≥30: подпись APK Scheme v2 или выше.
- Первоначальная debug-сборка подписывается **другим ключом**. При переходе на постоянную подпись Android потребует однократное удаление старой debug-версии. Сохраните все данные перед удалением.
- Используйте отдельные безопасные бэкапы ключа и пароля. Потеря ключа не позволит устанавливать новые версии поверх уже подписанных этим ключом.

## GitHub Actions: проверяемый release APK

**Подпись разрешена только для push в ветку `main` или ручного запуска `workflow_dispatch` из `main`.** На feature-ветках и в pull request собирается только debug APK, без доступа шага релизной сборки к signing secrets. Это не даёт черновой ветке автоматически использовать ключ выпуска.

Чтобы выпуск подписанных обновлений был возможен, добавьте в GitHub → Settings → Secrets and variables → Actions → New repository secret:

1. `EDITOR_KEYSTORE_B64`: base64 содержимого **ранее использовавшегося** `android-3d-editor-upload.jks` (одна строка).
2. `EDITOR_STORE_PASSWORD`: пароль этого хранилища.
3. `EDITOR_KEY_PASSWORD`: пароль ключа с alias `android-3d-editor`.

**Не присылайте секреты в чат и не размещайте их в репозитории.** Для лучшей защиты ограничьте `main` правилами защиты ветки и обязательным review. Для более строгой изоляции рекомендуется перенос ключа в GitHub Environment с разрешённой веткой `main` и требуемым утверждением — текущая конфигурация использует repository secrets.

На `main` при отсутствии любого ключа релизный шаг **завершается с ошибкой**, вместо прежнего зелёного статуса и отсутствующего APK. После `:app:assembleRelease` скрипт `tools/verify_editor_release.py` отклоняет APK, если:

- подпись v2 не проходит проверку `apksigner`;
- сертификат SHA-256 отличается от закреплённого выше;
- подписантов не ровно один;
- `applicationId`, `versionCode` или `versionName` не совпадают с `app/build.gradle.kts`;
- APK отсутствует или не читается.

Только прошедший проверку файл публикуется как артефакт `android-3d-editor-release`; отсутствие файла теперь считается ошибкой. Проверки скрипта включены в CI и работают без приватного ключа.

**Успешный CI feature-ветки подтверждает только debug-сборку и тесты, не релизную подпись.** Для релиза необходимы проверенная ветка `main`, прежний ключ и отдельная приёмка на устройстве. Из-за накопленных draft PR следует сначала проверить и интегрировать их в правильном порядке, а не запускать релиз напрямую из непроверенной feature-ветки.

## Локальная сборка

Настройте переменные `ANDROID_SIGNING_KEYSTORE_PATH`, `ANDROID_SIGNING_STORE_PASSWORD`, `ANDROID_SIGNING_KEY_PASSWORD`, затем `gradle :app:assembleRelease`. Проверка подписи: `apksigner verify --verbose --print-certs app-release.apk`. Результат должен содержать `Verified using v2 scheme: true`.

Не считать приложение установленным или протестированным по успешной подписи: проверка запуска и GLB — отдельная стадия.
