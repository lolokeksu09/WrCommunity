# WrCommunity Premium 2.0 — единый кандидат релиза (без публикации)

**Дата:** 27.10.2026. **Ветка:** `release/premium-2-final-candidate-2026-10-27`. **Базовый коммит исходников:** `6671666bcc64004daee36c2dcc52a84fe148d404` (последний проверенный коммит PR #55). **Зафиксированный main до начала:** `1077824c8a4d7d7c20f60ca8652e28805dee61eb`.

## Решение по интеграции

- Создать ровно **один** итоговый PR с этой ветки в `main`, без последовательных merge перекрывающихся PR #43–55. Ветка основана на конце их стековой цепочки; состав diff и наследование каждого исправления проверяются по файлам итогового PR.
- В отличие от публикации, создание Ready PR и запуск FULL не меняют VDS и рабочую базу.
- Никаких дополнительных UI-функций, реорганизации JS-бандлов, миграций или изменения политики Desktop E2E на финальном этапе. Подтверждённая малая оптимизация (preload `social.tsx` только на `/`) остаётся без расширения.
- Сохранить исходные PR открытыми до решения о едином merge; затем корректно оформить superseded без дополнительных merges (закрытие отдельных веток — отдельное действие, здесь не производится).

## Что должно войти

1. Аудит Premium 2.0 и измерения CLS; стабильный loading shell (#43–45).
2. Новый вид ленты и явные редакционные метки без искусственных пользовательских метрик (#46–47).
3. Изолированные проверки авторизованных экранов, адаптивности, скрытых профилей, клавиатуры, reduced-motion (#48–51).
4. Изолированная диагностика LCP и контролируемые сравнения, без production-модификации данных (#52–53).
5. Раннее получение существующего home chunk (#54), проверка на одинаковых 20 тестовых публикациях: медианный LCP 3376→3224 мс (−152 мс, лабораторные условия, не реальные пользователи) (#55).

## Критерии приёмки итогового PR

- [ ] Проверить полный `main...candidate` diff: присутствуют нужные UI-файлы, тесты и отчёты; отсутствуют неожиданные `server/`, SQL-миграции, секреты и модификации деплоя; временный `premium-preload-paired.yml` удалён.
- [ ] Получить **FULL на точном финальном head SHA**: `api-tests`, `browser-project (mobile-chromium)`, `browser-tests`, `integration`, `docker-smoke`, `quality-gate` = `success`. При новом коммите проверять заново.
- [ ] Сверить актуальный `main` и ruleset `25793011`; убедиться, что кандидат можно слить без конфликтов и дублирования.
- [ ] Убедиться, что работающий сайт и БД не менялись до отдельного решения о публикации. Автоматический Desktop Chromium E2E по решению владельца всё ещё отключён — не заявлять, что он прошёл.
- [ ] Внести в описание PR точный head SHA, ссылку на FULL, перечень фактически проверенных экранов, ограничений и действия по релизу.

## Открытые нефункциональные и эксплуатационные условия

- Реальный Chrome на Android: увеличение **200%**, клавиатура/IME и системный выбор файла; проверка TalkBack/скринридера и контраста в основных состояниях **ещё не подтверждены**.
- Field Core Web Vitals, INP, p75 LCP/CLS, реалистичные сети и изображения публикаций **не подтверждены**; цифры лабораторного A/B нельзя переносить на production.
- Пилотный UI-апдейт ≠ открытие публичной регистрации: внешний SMTP, возрастные/правовые условия, модерация и retention из `docs/implementation/STATUS.md` остаются самостоятельными блокерами **открытого запуска**.
- Слияние `main` может включить RELEASE → автоматическую сборку/резервное копирование/миграции/деплой на VDS и краткий перерыв в работе сайта. Не выполнять это действие до отдельного явного решения владельца о публикации Premium 2.0 на пилотном сайте.

## Последовательность публикации после разрешения

1. Проверить финальный main/PR head, правила и ручные release-gates или зафиксированное владельцем принятие ограничений.
2. Выполнить **один** защищённый merge интеграционного PR.
3. Проверить RELEASE для точного merge SHA: `api-tests`, mobile Chromium, Docker, `integration`; `deploy` и `vds-status` должны реально завершиться `success`, не `skipped`.
4. Проверить строгий HTTPS публичных `/` и `/login`, актуальный SHA VDS, здоровье PostgreSQL/worker/API и отсутствие `recovery_required`. При неудаче не объявлять релиз успешным.

**Одно следующее действие:** проверить итоговый diff и получить зелёный exact-head FULL для интеграционного PR. Публикация пока не авторизована.
