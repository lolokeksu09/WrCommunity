# Надёжные уведомления, модерация и формы

> Исполнять по завершённым этапам; пользователь утвердил исправления командой «Выполняй» после аудита. Объём: шесть подтверждённых дефектов. Компоновка онбординга, дополнительные предпочтения и lazy-loading остаются следующими предложениями.

**Цель:** сделать историю/счётчики и рассмотрение жалоб полными, а ошибки/конфликты форм разрешимыми без потери ввода.

**Архитектура:** существующие Fastify/PostgreSQL/React/worker/Docker. Расширения контрактов обратно совместимы: items/nextCursor, отдельный unread-count, error.fields и evidence.href/title/body. Новые таблицы/зависимости не нужны; допускаются только совместимые индексы для новых запросов.

## Объём и контракты

1. `GET /me/notifications`: limit 1–50, cursor, items/nextCursor; точность микросекунд и стабильный created_at/id. Отдельный `GET /me/notifications/unread-count` возвращает unread_count по всей доступной непрочитанной истории. Root использует его, не полный список. SQL выполняет пакетную ACL, автор скрытого комментария не раскрывается; подписи/ссылки соответствуют доступному объекту.
2. `GET /moderation/reports`: limit/cursor/state с устойчивым порядком; курсор привязан к виду/пользователю/фильтру. Жалоба получает разрешённые title/body/href для club/lfg/event и существующих типов. Недоступный/удалённый материал не раскрывается; модерационные роли и действия сохраняются.
3. Профиль: при VERSION_CONFLICT загрузить актуальный снимок, сохранить свой ввод, показать сравнение и явный повтор. Повторяет только изменённые пользователем поля, не перезаписывает посторонние изменения автоматически. Новый конфликт требует нового решения, не бесконечного retry. Добавить независимые убрать/вернуть аватар/обложку через существующие nullable поля PATCH.
4. Ошибки: error.fields с безопасными русскими сообщениями, без значений секретов. Регистрация проверяет ник до запроса; ошибки API привязаны к полям, aria-invalid/aria-describedby, фокус/прокрутка учитывают sticky-шапку. Общий alert остаётся для ошибок сети/формы.

## Основные риски и приёмка

- Уведомления: >200 записей, старое непрочитанное, ограниченное число SQL round trips, разные типы, hidden/block/deleted/revoked consent между страницами; actor_id скрытого автора не выходит в DTO. Отдельный счётчик не раскрывает недоступный материал.
- Курсоры: одинаковые даты/микросекунды/ID-порядок, отсутствие пропусков/дублей, invalid/cross-user/cross-filter cursor → 422; последняя страница не обещает лишнюю догрузку.
- Модерация: >100 открытых жалоб, член/посторонний/модератор, public/private LFG/event, отзыв членства. Жалоба не расширяет доступ; существующие полномочия и аудит решений сохраняются.
- Конфликт: изменены разные поля и одинаковое поле в двух вкладках; локальный ввод сохраняется, сравнение видно, повтор явный, свежая версия не скрывает второй конфликт. Изображения убираются и восстанавливаются до сохранения.
- Регистрация: кириллический/недопустимый ник, серверная ошибка поля, клавиатура, видимый фокус и ошибка на 390/1440; действующая защита CSRF не ослабляется.

## Проверки и продолжение

Промежуточно только новые API/связанные негативные случаи, два целевых E2E в обоих проектах, типы/сборка/L1. Полные локальные наборы после каждого шага не запускаются по запросу владельца. FULL/RELEASE сохраняют полное покрытие.

Локальный fallback: PGlite18.6 и Chromium153, изолированная среда из аудита; это не проверка конкурентности штатного PostgreSQL. Код не реализован. Следующее действие: сохранить план, затем API RED. Предыдущие отчёт/снимки аудита сохраняются как доказательства исходных дефектов.
