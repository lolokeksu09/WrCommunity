## Решения интерфейса и критерии приёмки

1. **Первые шаги.** В собственном профиле компактная секция: почта подтверждена / нужен переход к подтверждению; игровой сервер и хотя бы одна роль заполнены / нужен переход к карточке. Выполнение определяется серверными данными, не кликами. Далее два действия: найти игроков / найти команду. Секцию можно свернуть и вернуть; хранится только account-scoped настройка отображения, без содержимого профиля. Отказ хранилища не ломает страницу. Число готовых шагов относится только к двум проверяемым настройкам, не изображает состоявшуюся игру.
2. **Свои настройки в поиске.** В каталогах игроков и LFG авторизованный пользователь видит сервер и выбор одной своей роли. Кнопка «Использовать мои настройки» применяет только эти два фильтра, сохраняет остальные условия/режим, сбрасывает cursor. Изменения применяются только по нажатию. Сброс возвращает полный каталог. При пустой карточке — ссылка заполнения. Гость не получает приватный запрос `/me/profile`. В рекомендациях объяснить, что совпадения основаны на вручную указанных предпочтениях, без обещаний проверки Riot.
3. **Поиск команды.** Создание объявления объясняет, что роли относятся к искомым игрокам, а не автоматически копируются из своих. Разрешено предложить собственный сервер; сохранённый незавершённый ввод имеет приоритет. Лимиты полей совпадают с API: сервер 80, описание 2000, сообщение отклика 500, контакты 120 символов; хотя бы одна роль. Для pending/accepted/rejected/auto_rejected/cancelled показывать понятный следующий шаг; принятие не означает автоматического обмена контактами. Автор видит число загруженных откликов на рассмотрении и подсказку, что после принятия оба отдельно разрешают обмен. Закрытое объявление с `pending_policy=keep` не запрещает позднее решение существующей заявки.
4. **Контакты.** Два независимых индикатора: своё согласие и согласие напарника. Состояния: никто не разрешил / нужно своё согласие / ожидаем напарника / контакты доступны. Доступный контакт показывать только из `partner_contact`; не угадывать его. Кнопка обновления получает актуальное состояние; сохранение/отзыв повторно читает сервер. Ошибка запроса видна. После отзыва собственное поле очищается, согласие снова выключено. Отдельное предупреждение об уже сохранённых получателем копиях остаётся.

## Особое внимание при проверке

- Скрытый профиль с приватными предпочтениями: можно применить собственные настройки, публичность не меняется (задача 1).
- Смена аккаунта и недоступный storage: состояние секции не переносится к другому пользователю и не ломает страницу (задача 1).
- Несколько/старые/нестандартные роли и уже выбранные фильтры: явный одиночный выбор, без потери остальных условий; значения сверх лимита API не отправлять (задача 1).
- Принятый отклик при закрытом объявлении и pending-policy keep: разрешённые сервером действия остаются доступны (задача 2).
- Отзыв контакта другой стороной, повторное открытие, отказ сети и отменённая заявка: свежий ответ сервера, ошибка и повтор; старый контакт не выдавать за актуальный (задача 2).
