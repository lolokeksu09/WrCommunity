# Веб-интерфейс WrCommunity 1.0

Русскоязычная React SPA работает с `/api/v1` через cookie-сессию и CSRF-токен. Все публикации, участники, события и состояния загружаются с сервера. Данные продукта не заменяются localStorage или встроенными демонстрационными объектами. Незавершённый ввод редакторов поста, профиля, LFG и мероприятия сохраняется в памяти вкладки при переходах между разделами; при смене аккаунта или выходе этот ввод очищается. Пароли и токены не кэшируются. Для сохранения после полной перезагрузки поста предусмотрена явная серверная операция «Сохранить черновик». Оригинальная геометрическая графика и знак находятся в `web/public/brand.svg`; исходный `prototypes/home/v6/index.html` сохранён.

Часть представлений Screen Map объединена в один экран без изменения серверных правил: согласия входят в форму клубной личности, отклик — в карточку LFG, принятие и отклонение — в список заявок, отдельный экран мероприятий открывается из единой клубной ленты.

## Состояния и ограничения

Загрузка использует skeleton и индикатор перехода; формы — состояние выполнения, ошибки и обратную связь. Пустая выдача, отсутствие сессии, неподтверждённая почта, скрытый профиль и недоступный объект имеют отдельные сообщения. Ошибки 404 не различают удалённые и закрытые материалы. Проверки прав в интерфейсе служат навигации; сервер остаётся источником решения.

Карусель не воспроизводится автоматически. В интерфейсе нет чата, видео, выдуманной активности или синхронизации с игровыми API. Игровые поля и добровольные контакты заполняет участник.

## Проверка

- `npm run typecheck` — серверный и веб TypeScript.
- `npm run build:web` — сборка Vite в `dist/web`.
- `npm run test:e2e` — Chromium desktop и мобильный проект, настоящие API, PostgreSQL, SMTP/Mailpit и worker. Продуктовые сценарии работают с настоящим API; отдельный регрессионный тест намеренно имитирует одноразовый HTTP 503 при догрузке комментариев, чтобы проверить ошибку и повторный запрос.

E2E принимает `E2E_BASE_URL`, `E2E_MAILPIT_URL`, `DATABASE_URL` и при необходимости `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Обычные аккаунты создаются через регистрацию, а подтверждение выполняется реальным токеном из доставленного письма. Единственная привилегированная SQL-фикстура назначает тестовому аккаунту роль модератора в изолированной тестовой БД; она не создаёт обходной HTTP-маршрут. Без worker токен допускается читать из ожидающего email outbox, однако полный сценарий уведомлений требует работающий worker.

Тесты покрывают регистрацию/подтверждение/публикацию профиля, реальную загрузку изображения, посты и комментарии после reload, подписку/лайк/закладку, вложенный ответ и блокировку скрытого автора, закрытый клуб/псевдоним/одобрение/премодерацию, удаление комментария руководством, мероприятие/регистрацию, скрытый отклик LFG/принятие/контакты/отзыв, доставку/прочтение уведомления, предпочтения, жалобу/модерацию, восстановление/вход/сессии/экспорт/удаление аккаунта. Скриншоты реальной загрузки, главной, пустой выдачи и ошибки создаются на 360, 390, 430 и 1440 CSS px; проверяются отсутствие горизонтального переполнения, длинный текст и управление открытиями клавиатурой. Главная в карточках ограничивает длинный текст шестью строками и ведёт к полному тексту; сохранённое содержимое не сокращается. Переходы из незавершённых редакторов и смена аккаунта проверяются отдельным E2E.

Статические файлы обслуживаются через wildcard-маршрут; неизвестный `/assets/*` возвращает 404, а не HTML приложения. Штатный контейнер собирает и запускает согласованный серверный и веб-артефакт.

Фактические результаты запуска и визуальные свидетельства ведутся в `docs/evidence/` отдельно от перечня реализованных сценариев.

Приёмочный запуск 23.10.2026 завершился успешно: **22/22 E2E** в двух Chromium-проектах, 2 минуты, настоящие PostgreSQL/SMTP Mailpit/worker. Лог — `docs/evidence/e2e-tests.log`; viewport-снимки — `docs/evidence/screens/`. Проверка TypeScript и production-сборка веб-интерфейса также прошли.

## Мобильное создание публикаций — 24 октября 2026

В нижней мобильной панели размещено центральное действие «Создать». Оно выделено светлым прямоугольным знаком, без дополнительных анимаций и изменения общей тёмной темы. Для авторизованного игрока действие открывает `/posts/new`; для гостя — `/login?returnTo=%2Fposts%2Fnew`, чтобы после входа вернуться к редактору. Существующие четыре пункта и десктопная боковая панель сохранены. Контент не перекрывается нижней панелью на устройствах с `safe-area-inset-bottom`.

Браузерная регрессия: `tests/e2e/mobile-create-navigation.spec.ts` проверяет пять ссылок, гостевой переход, переход в редактор из авторизованного аккаунта и отсутствие горизонтального переполнения на мобильной ширине. В отдельном RED-запуске [Application CI](https://github.com/lolokeksu09/WrCommunity/actions/runs/40069064338) тест подтвердил исходное поведение: 4 ссылки вместо 5; остальные 28 E2E прошли. ## Главная лента и карусель — 24 октября 2026 (PR #7)

- Мобильная первая область стала компактнее: менее высокая карточка открытий, уменьшен промежуток до заголовка ленты и отступы публикаций. Текст публикаций увеличен с 14 до 15 CSS px без изменения содержимого и серверных правил.
- Дублирующие поиск и подпись раздела скрыты только в мобильном заголовке ленты — навигация и поиск доступны в шапке и нижней панели; десктопная навигация сохранена.
- «Свернуть» сохраняется в `sessionStorage` только как настройка отображения на время вкладки; публикации, аккаунты и другие данные продукта там не хранятся. При недоступном хранилище используется обычное локальное состояние.
- Перелистывание карусели происходит при направленном горизонтальном жесте (с учётом вертикального смещения), но не при вертикальной прокрутке. `touchcancel` сбрасывает жест; стрелки клавиатуры применяются только при фокусе самой карточки, не её внутренних ссылок и кнопок. Ручные точки и кнопка следующей карточки сохранены.
- Новый E2E: `tests/e2e/home-feed-ux.spec.ts` проверяет мобильное сохранение свёрнутого состояния после переходов SPA, вертикальный и горизонтальный жест, размер текста и видимость первой настоящей публикации на ширине 390 px. Исходные ошибки воспроизведены на [RED-запуске](https://github.com/lolokeksu09/WrCommunity/actions/runs/40070627543): 3 целевых мобильных сценария завершились неуспешно, 29 предыдущих E2E и 56 API-тестов прошли.

После слияния результат итоговой проверки и фактический SHA пилотного VDS следует сверять по GitHub Actions; эта документация сама по себе не подтверждает деплой.

## Просмотр изображений публикаций — 24 октября 2026 (PR #8)

На странице публикации и в любой ленте изображения (до четырёх на пост) открываются встроенным просмотрщиком на основе нативного `<dialog>` вместо автоматического перехода в новую вкладку. Сохраняются исходные медиа-URL и действующие серверные ACL: новые API, права доступа и хранилища не добавляются.

- Кнопки миниатюр имеют отдельные доступные подписи; полноэкранный просмотр работает на desktop и mobile. Для нескольких вложений доступны кнопки «Назад»/«Далее» и клавиши стрелок, для любого количества — «Закрыть просмотр» и Escape. При закрытии фокус возвращается к исходной миниатюре.
- Оригинальный файл можно открыть отдельно только явным действием «Оригинал». Фон модального окна затемнён; используется существующая сдержанная тёмная тема с учётом мобильных safe areas и `prefers-reduced-motion`.
- Браузерная регрессия: `tests/e2e/post-image-gallery.spec.ts` создаёт проверенный аккаунт в изолированном E2E, загружает два настоящих PNG через действующий редактор, публикует запись и проверяет просмотр/переключение/клавиатуру/закрытие/фокус. RED-сценарий воспроизведён на desktop и mobile в [Application CI](https://github.com/lolokeksu09/WrCommunity/actions/runs/40073385206): кнопки просмотра до правки отсутствовали.
