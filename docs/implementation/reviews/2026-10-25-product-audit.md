## Приоритет 1: исправить перед расширением пилота

### 1. Уведомления теряют непрочитанное и создают много SQL-запросов

Источник: [notifications/routes.ts:35–42](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/server/modules/notifications/routes.ts#L35), [root loader:73](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/web/src/main.tsx#L73).

**Воспроизведение:** 201 доступное уведомление об одном публичном посте; новые 200 прочитаны, самое старое не прочитано. GET `/me/notifications` вернул 200 элементов, все прочитаны, без курсора; в БД осталась одна непрочитанная запись. Root считает badge по этой обрезанной выдаче и получает 0. История недоступна через интерфейс.

Тот же один запрос в этой фикстуре выполнил 403 вызова pool.query из-за последовательной проверки каждого элемента. Root загружает список ради счётчика, поэтому такая работа попадает и в общие загрузки/повторную валидацию. Количество SQL измерено; production-латентность из него не выводилась.

**Доработка:** курсорная история с актуальной ACL, отдельный корректный счётчик непрочитанного и пакетная проверка доступов/авторов. Счётчик не должен раскрывать недоступные объекты. Приёмка: старое доступное непрочитанное достижимо; badge верен; скрытие/блокировка между страницами соблюдаются; нет SQL-запроса на каждый элемент ради шапки.

### 2. Модерация не показывает доступный объект жалобы

Источник: [moderation/routes.ts:32–37](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/server/modules/moderation/routes.ts#L32), [ModerationReport:37](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/web/src/notifications.tsx#L37).

**Воспроизведение:** жалоба на публичное LFG принята; тот же модератор читает объявление с HTTP 200, но GET жалобы даёт evidence=null. В интерфейсе написано, что содержимое недоступно, ссылки на объявление нет, при этом есть действия сохранения решения/скрытия. По коду материал формируется только для post/comment/profile; club/lfg/event не обработаны. Для LFG дефект подтверждён исполнением; club/event установлены статически.

**Доработка:** представления материалов для всех поддерживаемых типов, ссылка на доступный объект и точные состояния «доступно / удалено / нет права». Использовать существующую ACL, не выдавать скрытые данные через жалобу. Приёмка: доступный LFG виден в жалобе, недоступный остаётся защищённым; решения модерации имеют понятный контекст.

[Снимок текущей жалобы](../../evidence/product-audit-2026-10-25/moderation-missing-evidence.png).

### 3. Старые открытые жалобы оказываются за пределом очереди

Источник: [moderation/routes.ts:31](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/server/modules/moderation/routes.ts#L31), [ModerationReports:36](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/web/src/notifications.tsx#L36).

**Воспроизведение:** 102 открытые жалобы; фильтр state=open вернул только новые 100, старая нерассмотренная отсутствует, курсора нет. Из списка её нельзя открыть, пока она остаётся за этим окном; прямой URL возможен только при известном ID.

**Доработка:** полная курсорная очередь, устойчивый порядок и видимое число/признак оставшихся элементов. Аналогичные жёсткие окна есть у собственных LFG/откликов, каталога клубов и некоторых журналов; эти места обнаружены статически и требуют отдельной приёмки, не объявлены все воспроизведёнными. Приёмка: старое открытое обращение достижимо после догрузки без дублей/пропусков и с теми же правами.

## Приоритет 2: формы и управление профилем

### 4. Конфликт профиля заканчивается потерей незаписанного ввода

Источник: [ProfileEditor:37–38](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/web/src/auth.tsx#L37), [useTask/useFormDraft](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/web/src/ui.tsx#L5).

**Воспроизведение:** открыть редактор, ввести новое имя; другим запросом обновить профиль. Первое и второе сохранение из формы дают 409 и «Профиль изменился. Обновите страницу…». Версия остаётся прежней; после reload введённое имя теряется. До reload текст сохраняется в форме, но штатного разрешения конфликта нет.

**Доработка:** загрузка актуальной версии с сохранением локального ввода и явным разрешением конфликта. Не перезаписывать молча изменения другой вкладки. Приёмка: пользователь может восстановить/сопоставить свой текст и завершить сохранение, не попадая в повторный 409.

[Снимок конфликта](../../evidence/product-audit-2026-10-25/profile-conflict.png).

### 5. Ошибка регистрации техническая и скрывается под мобильной шапкой

Источник: [AuthPage:11–12](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/web/src/auth.tsx#L11), [Feedback/Field](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/web/src/ui.tsx#L6).

**Воспроизведение:** ник «игрок» проходит HTML checkValidity, сервер возвращает 422 с текстом `handle: Неверная строка: должна соответствовать шаблону /^[a-z0-9_]{3,32}$/`. Ни одно поле не получает aria-invalid, фокус уходит в BODY. При 390×844 alert находится на y≈6–67 под sticky-шапкой высотой 64: ошибка почти не видна после отправки.

**Доработка:** понятная проверка ника до запроса и структурированные ошибки полей от сервера; aria-invalid/aria-describedby, фокус первого ошибочного поля, прокрутка с учётом шапки. Общий alert сохранить для сетевых/общих ошибок. Приёмка: кириллический ник объясняется русским текстом рядом с полем, ошибка видна и доступна с клавиатуры/скринридера.

[Viewport после ошибки](../../evidence/product-audit-2026-10-25/signup-error-viewport.png).

### 6. Из редактора нельзя убрать аватар и обложку

Источник: [ProfileEditor:37–38](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/web/src/auth.tsx#L37), [profileSchema](https://github.com/lolokeksu09/WrCommunity/blob/5617d4567087983e8b2a6b396aadd3b6df74acf2/server/modules/profiles/routes.ts#L18).

**Воспроизведение:** загрузить тестовое изображение и назначить аватаром/обложкой. Видны два preview и единственная кнопка «Сохранить изменения»; действия удаления нет. API уже допускает avatar_id/cover_id=null, интерфейс предоставляет только замену загрузкой.

**Доработка:** отдельное действие убрать изображение с превью результата и сохранением существующим PATCH. Приёмка: оба изображения можно удалить независимо, отменить несохранённую правку и увидеть нейтральную заглушку.

[Редактор с двумя изображениями](../../evidence/product-audit-2026-10-25/profile-avatar-no-remove.png).

## Дизайн: следующие улучшения, не подтверждённые аварии

- **Компактный завершённый онбординг.** На просмотренном профиле блок 2/2 остаётся развёрнутым и занимает большую часть первого экрана. Предложение: компактное завершённое состояние с возможностью раскрыть, учитывающее сохранённый выбор пользователя. Игровую карточку и реальные действия сделать доступнее по высоте. Источник: web/src/player-journey.tsx:16–30.
- **Иерархия длинной игровой формы.** Сгруппировать сервер/роли/ранг отдельно от дополнительных предпочтений; оставить контроль публичности рядом с каждым полем. Предложить понятный выбор часового пояса и примеры значений. Это предложение продукта/дизайна; сохранение нестандартных допустимых ролей и ручных данных остаётся обязательным.
- **Единый язык ошибок/действий.** Сначала решить пункты 4–6: ошибки рядом с полями, явные действия с изображениями, предсказуемые busy/focus/retry. Внешний вид уже имеет рабочую мобильную навигацию; вывод об обязательном полном редизайне из аудита не следует.

## Код: последующий технический патч

- Выделить повторяющиеся ошибки/конфликты форм в проверяемый контракт UI/API и разгрузить крупные компоненты auth/clubs/social при их изменении. Сжатые многотысячные строки затрудняют ревью и сопоставление ошибок с кодом; форматирование отделять от изменения поведения.
- Разделить загрузку маршрутов: main.tsx статически импортирует все основные экраны. Текущая production-сборка дала JS 503.20 kB, gzip 149.40 kB и предупреждение Vite 500 kB. Route lazy-loading — кандидат на замер первого запуска; измерения скорости реальных телефонов не выполнены, предупреждение не является аварией.
