# WrCommunity — Screen Map & User Journeys v1

**Версия:** 1.0-draft · **Дата:** 23 октября 2026 г.  
**Связанный документ:** [Functional Specification v1](./Functional-Specification-v1.md)  
**Статус:** предлагаемая карта мобильных экранов, маршрутов, состояний и переходов для разработки; маршруты **не созданы на действующем сайте**.

## 0. Принципы

1. **Навигация под ежедневное использование.** Главная — живой контент, не рекламная витрина. Клубы и LFG доступны в 1–2 касания, без обязательной карусели по каждому запуску.
2. **Единый язык экранов v6 Editorial Social.** Тёмная сдержанная палитра, читаемая типографика, один визуальный акцент, обложки только там, где несут смысл. Никаких фейковых цифр, чатов или игровых API.
3. **Безопасность отдельна от маршрутизации.** Видимость кнопки не заменяет серверную ACL; любые закрытые данные, предварительные публикации и запросы проверяются на сервере.
4. **Маршруты с неизменяемыми ID.** Символьные пути ниже ориентировочные (`:userId`, `:clubId`, `:postId`, `:eventId`, `:lfgId`). URL не являются утверждённым API, не выдают маршруты уже существующего сайта.
5. **Клубная лента — единый поток.** Анонсы мероприятий появляются как карточки среди постов; отдельный экран события открывается из карточки. Исторически закрытый контент остаётся закрытым.
6. **Контекстные формы — возвращение.** После входа/верификации возвращать человека к объекту, но не отправлять отложенное действие автоматически.

## 1. Основная мобильная навигация

**[DESIGN] Нижняя панель (четыре раздела):** `Лента` → `/`, `Поиск` → `/discover`, `Клубы` → `/clubs`, `Профиль` → `/me`. Центр уведомлений открывается из кнопки в шапке (значок с понятной меткой), поиск доступен из шапки и вкладки. В контексте клубной страницы действует локальное меню «О клубе / Участники / Управление» по правам. Экран публикации, LFG, заявки или мероприятия открывается внутри существующего маршрута; навигация назад возвращает к месту открытия и позиции прокрутки.

```
WrCommunity /
├── Лента (Все / Подписки) ── Пост ── Комментарии / Ответить
│   ├── Создать пост ── Редактор ── Предпросмотр/Отправка
│   └── Компактная сворачиваемая карусель открытий
├── Поиск
│   ├── Люди ── Игровой профиль ── Подписаться
│   ├── Ищу команду ── Объявление ── Отклик
│   │                  └── Автор объявления ── Заявки ── Принять/Отклонить
│   └── Темы и публичный контент
├── Клубы ── Каталог ── Клуб
│   ├── Создать клуб ── Данные ── Доступ ── Проверка ── Панель владельца
│   ├── Вступление ── Клубная личность (hidden) ── Согласие ── Статус
│   ├── Единая клубная лента ── Пост ── Дерево комментариев
│   ├── Единая клубная лента ── Событие ── Участвовать/Отменить
│   ├── Состав и правила
│   └── Управление ── Заявки / Премодерация / Роли / Настройки
├── Профиль ── Мой профиль ── Редактирование / Приватность / Игровые данные
│   ├── Подписки / Закладки / Мои клубы / Мои LFG
│   └── Настройки / Уведомления / Блокировки / Удалить аккаунт
└── Уведомления ── Список ── Разрешённый исходный объект
```

## 3. Ролевая навигация и отсутствие утечек

| Сценарий | Гость | Публичный профиль | Скрытый профиль | Руководство клуба |
|---|---|---|---|---|
| Глобальная лента | Только доступные посты | По доступу | По доступу; свои скрытые материалы не публикуются публично | Те же глобальные правила |
| Список игроков | Только public | Public, кроме заблокированных | Не появляется в публичной выдаче | Не открывает скрытые профили |
| Карточка закрытого клуба | Описание/правила/вступить, без ленты и состава | Аналогично пока не участник | Аналогично пока не участник | Доступно по текущему членству и полномочиям |
| Клубная лента members_only | Нет | Только при действующем членстве | Только при членстве и согласии | По членству |
| Состав публичного клуба для неучастника | Только public членов | Только public членов | Только public членов | Может видеть разрешённые клубные данные при членстве |
| Клубная личность hidden члена | Нет | Только при членстве в том же клубе | Только при членстве | Только необходимый ограниченный набор |
| Комментарии публичного клубного поста | Чтение публичных; не писать | Пишет только член клуба | Новые комментарии запрещены | По основному профилю/членству |
| Комментарии закрытого клубного поста | Нет | Член клуба может писать | Член клуба пишет с клубной подписью | По тем же правилам |
| Участие в публичном мероприятии | Нет | Только члены клуба | Только члены клуба; не публично | По тем же правилам |
| Создание LFG | Нет | Да | Нет | Глобальная видимость, не роль клуба |
| LFG-отклик | После входа | Да | Да, явное раскрытие ника только автору | По обычным правам |

**Не выводить** скрытых участников через общее число, которое можно вычесть из публичного списка; не подменять скрытый объект рекомендацией/preview; не помещать закрытую клубную обложку комментария в доступный по постоянному публичному URL CDN.

## 4. Основные переходы (screen-to-screen journeys)

### J01 — гостевой просмотр и регистрация

`SOC-01 → SOC-03 → действие → SOC-06 / SOC-07 → SOC-08 → SOC-03 → явное повторное действие`.

Если объект больше не доступен, вместо автоматического действия показать безопасное состояние недоступности.

### J02 — создание клуба

`CL-01 → [проверить U + email + public + антиспам + владеет < 3] → CL-02 → CL-03 (два обязательных выбора) → CL-04 → CL-14`.

При ошибке сохранить заполненное; при повторной отправке избегать создания двух клубов; `CL-14` сразу после успешного создания, без искусственных публикаций.

### J03 — скрытый пользователь вступает свободно

`CL-05 → CL-08 → CL-09 (handle или псевдоним, аватар, роли) → CL-10 (явное согласие) → CL-11 active → CL-05`.

При отсутствии согласия — нет членства; скрытый основной профиль не открывается. При смене правил на approval на сервере переход к заявке, а не молчаливое автоматическое вступление.

### J04 — вступление по заявке и отказ

`CL-05 → CL-08 → [hidden: CL-09/CL-10] → CL-11 pending → CL-12/13 → approved→CL-11 active ИЛИ rejected→CL-11 (причина, если указана)`.

Предпросмотр заявки доступен только уполномоченным; пока pending ни лента members_only, ни состав не открываются заявителю.

### J05 — выход или отзыв согласия

`CL-11 → CL-19 (предупреждение об истории подписи) → подтверждение → CL-05 как неучастник`.

При отзывании согласия скрытым пользователем членство прекращается автоматически после подтверждения; исторические клубные ник/аватар у прежних комментариев остаются только в прежней аудитории, основной профиль недоступен.

### J06 — смена приватности владельцем

`SOC-14 (public→hidden) → проверка текущих владений → если ≥1: блокировать, объяснить → CL-18 передача владения после принятой процедуры → SOC-14`.

Передача владения ещё **[OPEN]**. Нельзя переключить owner в hidden либо автоматически удалить клуб без решения.

### J07 — публикация в клубе

`CL-05 → CF-01 → отправить → CF-02 pending → CF-05 → CF-06 approve/reject → CF-03 при опубликовании`.

CF-06 применяет запрет самопроверки; у владельца исключение лишь при формально определённом отсутствии другого проверяющего. Новая редакция одобренного поста ждёт отдельно, старая видима.

### J08 — обсуждение закрытой публикации

`CL-05 → CF-03 → [membership + permission + blocked checks] → комментарий → многоуровневая ветка`.

Для hidden показывать клубную личность. Длинные ветки сворачивать; глубина визуального отступа не обязана совпадать с логической глубиной. При потере членства закрытые ветки перестают отображаться.

### J09 — создание и участие в событии

`CL-05 → EV-01 (роль разрешена) → EV-02 / карточка в CL-05 → «Участвовать» (только CM) → `registered` / `full` → EV-05`.

Операция участия атомарная; при отказе по заполненности показать «Мест нет». Изменения/отмена — `EV-04` и внутренние уведомления для имеющих доступ.

### J10 — поиск игрока и объявление LFG

`DIS-01 → DIS-02 (сервер/роль) → DIS-03 → DIS-05 → DIS-06 → DIS-08`.

Автор: `DIS-03 → DIS-04 (срок + политика pending) → DIS-05 → DIS-09 → DIS-10 → DIS-12 (взаимное согласие)`.

Hidden может отправить адресную заявку, но не перейти к `DIS-04`. Истечение запрещает новые заявки; политика автора применяется к pending без скрытой переинтерпретации.

### J11 — глобальная блокировка

`SOC-11 → «Заблокировать» → подтверждение → убрать две подписки/взаимные реакции → фильтрация комментариев, упоминаний, LFG и рекомендаций`.

В одном клубе обе стороны остаются членами по согласованному правилу. Исторические комментарии фильтруются сервером для каждой стороны, не удаляются для третьих лиц.

### J12 — уведомление о закрытом объекте

`SOC-18 → открыть событие → сервер повторно проверяет ACL → открыть доступный объект ИЛИ безопасное недоступно без тайного превью`.

## 5. Контракты экранов и общие состояния

Для каждой страницы с чтением: `loading`, `ready`, `empty`, `no_access/not_found`, `error`, `offline`. Для операций: `idle`, `editing`, `submitting`, `success`, `validation_error`, `conflict`, `forbidden`, `temporary_error`. У ошибок редактирования не терять введённое.

| Компонент | Правило UX |
|---|---|
| Шапка | Контекстный заголовок, возврат, поиск/уведомления по месту; не загромождать |
| Нижняя навигация | Четыре вкладки, ясная активная, не перекрывает контент и клавиатуру |
| Клубная карточка | Название/описание/обложка, видимость ленты и тип вступления; нет фальшивой активности |
| Вложенные комментарии | Сворачивание веток, поэтапная загрузка, сохранение контекста ответов, читаемость 320 px |
| Премодерация | Автор видит `pending/rejected`, читатели видят только одобренное |
| Смешанная клубная лента | Обычные посты и карточки событий с разными метками типа, единая прокрутка |
| Последнее место | Нажатие блокируется на время операции; результат отвечает сервер |
| Согласие hidden | Отдельный явный экран со списком разрешённых полей и предупреждением о старой подписи |
| Выход из клуба | Предупреждение о потере доступа и сохранении прежнего ника/аватара в исторических комментариях |
| Изменение ленты | Подтверждение открытия; старые закрытые материалы не становятся публичными |
| Открытие скрытого профиля | Не ссылаться на личный профиль даже из клубной личности или LFG-заявки |
| Служебные сообщения | После отклонения заявки причина только если указана; модераторские данные не показывать |

## 6. Сценарии ошибок и права на отмену

| Сценарий | Точка контроля | Что увидит пользователь |
|---|---|---|
| Гость пробует социальное действие | До mutation | Вход и возврат в прежний контекст, без автоматического действия |
| Hidden пытается создать клуб/LFG | При открытии и перед mutation | Требование открытого профиля; не менять видимость самостоятельно |
| Занятый клубный псевдоним | Ввод + сервер | Ошибка у поля, предложить иной псевдоним |
| Дублирование заявки | Серверная уникальность | Уже существующий статус, без второй заявки |
| Одобрение после отзыва согласия | Транзакция/конфликт | Заявка недействительна, членство не создаётся |
| Попытка просмотра старого закрытого поста | ACL каждого объекта | Не показывать, даже если текущая лента публична |
| Одновременные модераторы | Версия записи + атомарное состояние | «Решение уже принято» без двойного действия |
| Скрытый комментирует публичную клубную запись | Серверная проверка | Понятный запрет по состоянию профиля |
| Блокированные пытаются адресно ответить | Взаимный blocked(A,B) | Операция недоступна; новые уведомления не создаются |
| Регистрация при полном мероприятии | Атомарная проверка мест | «Мест нет», не создавать запись |
| LFG истёк до отправки отклика | Повторная серверная проверка времени | «Объявление завершено», не отправлять заявку |
| Нет сети после отправки | Idempotency key / повторное чтение | Возможность узнать исход и повторить безопасно |
| Удаление аккаунта | Глобальное правило удаления | Прежний handle/клубный ник/аватар не остаются в сохраняемых комментариях |

## 9. Нерешённые решения перед детализацией макетов

- Полномочия клуба для рассмотрения заявок, исключения участников и редактирования правил; безопасная передача владения.
- Точные поля форм, длины, типы файлов, обработка ошибок и доступность изображений.
- Публикация мероприятия скрытым руководителем; судьба участия после выхода/исключения из клуба.
- Единый UX просмотра одобренных версий постов при редактировании и обработки отказа.
- Исторический клубный аватар при отзыве согласия и последующем удалении аккаунта: политика медиа и приватности.
- Отображение публичных счётчиков при hidden участниках, исключающее раскрытие через арифметическую разность.
- Ограничение нагрузки на глубокие деревья, действия против спама, автоматическое закрытие LFG и удаление данных.
- Правила добровольного обмена игровыми контактами после принятия заявки.

Существующий интерактивный прототип главной v6 — **визуальный ориентир**, не действующая имплементация этих маршрутов. Изменять прототип не требуется, пока не утверждены экранные контракты.
