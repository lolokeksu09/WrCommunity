# Проверки L1–L5 — Project Workflow Standard 1.4-rc3

Режимы документации Light/Full **не влияют** на обязательность проверок.

| Уровень | Назначение | Обязательное доказательство |
|---|---|---|
| L1 | Корректность текста, Kotlin и Gradle | Компиляция, проверки заголовка GLB, ссылки |
| L2 | Изменённый пользовательский сценарий | Открытие допустимого GLB и отказ на повреждённом файле |
| L3 | Связанные модули и границы доверия | SAF → проверка → модель в SceneView на тестовом устройстве |
| L4 | Готовность кандидата | Все обязательные gates, exact commit и проверенный APK |
| L5 | Поставленная версия | Установка и запуск выбранного APK на реальном Android |

Применимые проверки выбираются по риску. Ошибки и безопасность данных требуют позитивного и негативного сценария. Если эмулятор/телефон или Android SDK недоступны — отмечать «недоступно», а не «успех».

Обязательные проверки текущего этапа: CI Gradle assembleDebug, unit-тесты заголовка GLB; до утверждения Android-поставки — фактическое открытие и вращение пользовательского GLB.

Skips/pending/cancelled не считаются успешными. Исключения допускаются только при явном разрешении владельца с EXC-ID, версией, scope, сроком и риском. Исключение не меняет фактический статус теста и не переносится на другие версии.

Отдельно фиксировать «готово в коде», «проверено», «PR открыт», «опубликовано». Успешная сборка не подтверждает интерфейс. Разрешение на создание PR не равно разрешению на merge, релиз или операции с сервером.
